# 原生 AI 助手：受控画布编辑

来源：[Notion TK-42](https://app.notion.com/p/4091a252e211814b8d99e6fd151cae10)。
实施及验收：2026-10-30 至 2026-10-31。

## 已实现

- 七种固定操作：`create_rectangle`、`create_text`、`create_frame`、
  `set_text`、`set_fill`、`set_bounds`、`set_corner_radius`。全部通过 Zod 严格校验。
- 矩形创建支持可选 `borderRadius`；`set_corner_radius` 修改现有矩形的四角统一圆角。
  参数须为非负有限数，`0` 恢复直角；其他图层类型不能使用该修改工具。
  上下文和预览保留四个独立圆角值，执行后逐一回读核验。
- 模型仅能规划操作；服务端保存计划并绑定登录账号、文件、页面、编辑器会话和选区。
  `/api/agent/confirm` 接收计划 ID，不接受替换操作内容。
- 面板逐项显示目标、属性变化及选区外操作提示，提供确认和取消按钮。
- 生成写计划及确认时，用登录 Cookie 核对后端文件编辑权限。
  MCP 凭据来自服务端当前账号，浏览器不能提交其他用户身份或模型服务地址。
- MCP 原生入口仅注册读取上下文及准备、执行、取消计划的固定工具。
  注册信息标记读写权限，不向模型提供执行或取消入口。
  插件只调用固定 API，不使用 `eval`、`new Function` 或 `execute_code` 实现写入。
- 插件执行前核验当前文件、页面、选区及目标快照；页面、文件、选区及目标图层变化使旧计划失效。
  每一步回读真实对象，校验文本、填充、位置、尺寸及创建属性。
- 返回每步状态、对象 ID、前后属性和失败提示。失败后跳过后续步骤。
  已验证的成功步骤、可能已修改的失败步骤和未执行步骤分别反馈。
- 服务端及插件均防止重复执行。网络失败后的未知结果不自动重放。
  取消会同时关闭服务端确认权限并移除插件内预览。
- API Key 只在服务端；计划参数和画布读取结果不写入常规桥接日志。

## 限制

- 每轮最多 20 步，选区最多 40 项；只能修改当前快照内明确指定的现有对象。
  新建对象位于当前页面根级；`create_frame` 使用 Plugin API 的 `createBoard`。
- `set_fill` 将全部填充替换为一个纯色填充；预览明确展示这一行为。
- 计划有效期 5 分钟，仅保存在进程内。Agent 或插件重载后需要重新生成。
  本机运行一个 Agent 进程；多实例部署需要固定会话路由或共享计划存储。
- 已锁定、隐藏或类型不符的目标会被拒绝。尺寸变化可能间接影响容器子图层；面板提示这一点。
- 每步最多等待布局 5 秒，批次超过 10 秒后不再开始新步骤，避免长时间占用撤销分组。
- 每轮使用原生 `undoBlockBegin` / `undoBlockFinish`；失败不承诺原子回滚。
  停止等待结果不能取消已经提交的修改。用户可以检查画布并使用原生撤销。
- 前后属性与执行结果随计划过期清理，不是长期审计记录。
- 权限核对目前读取 `get-file` 的 `permissions.canEdit`；大文件会有额外读取成本。

## 真实验收

使用本机 `https://localhost:3449`，模型 `glm-5.3-flash`，文件「新建文件 1」的「Page 1」。

1. 请求将选中的 Rectangle 改为 `#0000FF`。计划显示原填充 `#B1B2B5`、
   目标对象 ID 和新填充；确认前画布保持灰色。
2. 取消该计划后，在原生属性面板核对填充仍为 `#B1B2B5`。
3. 重新生成并确认。真实矩形变蓝，面板显示「已执行并验证 / 回读一致」。
4. 原生 `Ctrl+Z` 恢复灰色，`Ctrl+Shift+Z` 恢复蓝色；再次撤销恢复验收前填充。
5. 请求在页面根级创建「AI Phase2 验收」矩形：位置 `(680, 189)`，尺寸 `100 × 60`，
   填充 `#00AA88`。确认前显示新建对象及选区外操作提示。
6. 确认后画布出现真实绿色矩形，面板回读一致；图层 ID 为
   `f82c491e-f93e-806a-8008-de99cfcd5880`。使用原生撤销移除验收矩形。
7. 最终版本请求将当前蓝色矩形改为绿色，仅生成预览后取消。
   面板显示「已取消计划，未修改画布」，服务端与插件取消调用成功，矩形仍为蓝色。
   验收截图保存在 `tmp/phase2-cancel-verified.jpg`（忽略文件）。

真实联调发现插件沙箱不提供 `crypto.randomUUID`，已将计划 ID 改为服务端生成。
普通用户写操作仍经过固定工具，验收没有通过任意代码通道修改画布。
文本、画板及位置尺寸的工具覆盖由插件自动测试验证，未将其记为全部浏览器实测。

### 矩形圆角增补（2026-10-31）

- 示例：「把选中的矩形四个角统一设为 16 的圆角，只修改圆角。」
- 真实预览显示原值 `12 / 12 / 12 / 12`，目标统一半径为 `16`。
  确认后回读一致，原生属性面板也显示圆角 `16`。
- 原生撤销恢复原值 `12`，验收未保留该临时修改。
- 截图：`tmp/radius-verified.jpg`（忽略文件）。
- 新建矩形可同时指定圆角；本次支持四角统一设置，尚未提供逐角修改工具。

### 旧插件版本不匹配修复（2026-10-31）

- 「将矩形改成圆角」后补答「8」曾提示计划失效。服务端日志明确显示：
  当前编辑器运行的旧插件只接受六种操作，拒绝 `set_corner_radius`。
- 为内置插件每次初始化生成新的资源地址，避免浏览器缓存继续提供旧代码。
  已经运行的旧插件仍需刷新编辑器并重新连接。
- 将旧插件的工具判别字段校验错误映射为明确的版本过旧提示；不向用户回显原始异常。
- 网络边界回归测试复现原错误并验证提示；前端测试验证两次初始化使用不同插件资源地址。
- 浏览器按「将矩形改成圆角」→ 助手追问 →「8」原样复验，成功生成
  `0 / 0 / 0 / 0` 到统一圆角 `8` 的待确认计划，尚未修改画布。
  截图：`tmp/radius-followup-fixed.jpg`（忽略文件）。
